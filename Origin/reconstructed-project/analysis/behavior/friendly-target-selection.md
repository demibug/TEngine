# 友军索敌行为

1. BattleManager 使用单位表现中心点、`attackRange` 和阵营调用 `EnemyManager.queryTargets`。
2. EnemyManager 使用第四轮恢复的 80px 空间格、阵营过滤、死亡/不可攻击过滤，以及圆形攻击区与 80×80 敌人 AABB 相交判定。
3. 返回顺序不排序，来源是格子扫描顺序与每格 Set 插入顺序。
4. 刀兵 `Nx` 会再次查询，而不是复用 BattleManager 的候选数组。
5. 刀兵选择距离最小的候选，但原代码存在非对称比较：首候选使用友军和敌人的左上角，后续候选使用双方中心点。本轮原样保留。
6. 没有 Boss 优先、低血优先或路径进度排序。
7. 多个友军可以同时攻击同一 Mob0；`PlacementReservationRegistry` 只参与放置冲突，不限制攻击者数量。
8. 目标在真正攻击调用前离开范围时，单位返回 `UnitIdle`；延迟攻击已经创建后，只要目标仍存活且阵营有效，原攻击会按时间线结算。
