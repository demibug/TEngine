## 网络

1. 当前 TEngine 是否计划接入游戏长连接？如果接入，传输是 TCP、WebSocket、HTTP 长轮询还是已有外部插件；所有权属于哪个 Module？
2. 协议是否自带 requestId/responseId？如果只有消息类型，哪些请求允许并发、如何区分同类型回复？
3. 断线时 pending 请求的标准结果是 Disconnected、Retrying、Timeout 还是 Cancelled？是否按连接 generation 丢弃迟到回复？
4. 连接失败重试和已连接后的断线重连是否同一个状态机？哪些请求可安全重放，哪些请求必须由业务重新发起？
5. 心跳超时是否只报告 liveness，还是负责触发 reconnect？网络层、登录层、资源下载层的 timeout 是否需要统一错误码？
6. 当前工程没有代码确认的网络初始化链；主工程需要提供入口、程序集和平台条件编译证据后再收敛 S05-C001/C002。

2. 当前运行时表访问的真正入口、生成程序集、资产地址和 YooAsset package 何时初始化？是否支持 editor simulate、单机和热更一致路径？
3. 配置包是否有 schema hash、生成器版本、资源包版本或字段迁移号？字段删除、类型变化、枚举变化和缺失资产如何报告？
4. 缺表、空表、decoder 错误、资产未加载、版本不匹配是否要区分为可重试、可降级和致命错误？

## 持久化

1. 哪些数据是设置，哪些是诊断，哪些是本地缓存，哪些是必须恢复的存档？它们不应默认共用 PlayerPrefs。
2. 是否要求多字段一致提交？若要求，PlayerPrefs 多 key 写入与直接 File.WriteAllText 都不能直接作为事务保证。
3. 版本不兼容时是清除、迁移、回滚还是降级到默认值？版本号属于每个 key、每个文件还是整个存档 schema？
4. 当前 Utility.PlayerPrefs 的用户前缀何时设置、账号切换时如何清理；是否需要防止旧用户 key 泄漏到新用户？
