# Slave A：参考工程两步热更新调查

## Role
使用 `$slave-executor`（`C:\Users\Administrator\.agents\skills\slave-executor\SKILL.md`）的单代理工作方式，但本任务只调查并编写文档，不实现代码。本提示词的调查范围优先于技能的默认实施流程。不得自动分派代理、创建会话、切模型或调用 master。遵守适用 AGENTS.md/AGENT.md/CLAUDE.md，以源码、程序集配置、资源采集配置、构建脚本为事实来源。

## Objective
核查 `D:\Work\SAUnity\ProjectOld` 的“两步热更新”真实含义，形成可用于向 TEngine 迁移的证据报告。不要先假定两步就是 DLL/资源分开下载。

## Investigation contract
1. 追踪启动入口、阶段一下载与程序集加载、阶段二入口与资源更新、进入游戏的完整调用链；每项关键结论给出绝对文件路径、行号、符号。
2. 核实各阶段运行于 AOT 或热更程序集，哪些更新逻辑本身可热更；核查 asmdef、HybridCLR 设置与构建收集规则。
3. 查版本发现、包划分、代码/资源版本绑定、发布顺序、失败重试、离线/断网、强更、缓存清理、取消/退出、重复进入、程序集不可卸载、AOT metadata、编辑器与真机差异。
4. 分清实际配置启用的路径、可选/遗留路径、文档设计意图、从未证明的推断；缺失能力不要推断成存在。
5. 列出可迁移机制、不能照搬的工程耦合和已发现缺陷，附迁移前验证场景。
6. 对每个阶段记录实际资源包、标签、Bundle 划分与依赖闭包，验证“代码支持”是否由当前平台宏/序列化配置实际启用；不要将注释或方法命名作为执行事实。重点核验 metadata、启动器及其 UI 能否在第二阶段之前完整获得。
7. 检查正常更新及失败回退是否切换 manifest；若程序集已经加载，核验切换资源版本是否可能形成混合版本。检查“成功版本”何时持久化，以及是否按基础 Player/平台/渠道隔离。

## Constraints
参考工程完全只读。当前工程只作为文档输出位置，不调查其实现。不修改源码、配置或其他人的文档。不启动 Unity、不执行构建、不联网；这是对本地固定版本源码的调查。不要依赖巨量全文输出；定向搜索入口和调用者。即使输出位置已有报告，也仅视作未经审查的草稿，独立核实源码后允许重写本任务负责的报告。
