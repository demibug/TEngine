## 结论

原工程的“地图生成”不是运行时随机拼图，而是从 4 张固定的 8×10 格子地图中按 `mapIndex` 选择一张，复制到运行时地图 `pe`，再计算双方的 A* 路径并铺设 Laya 瓦片。

铲子也不是直接创建一个可放兵的特殊坐标。它是一个可拖拽的道具对象：

```text
铲子卡牌/铲子广告
        ↓
刷新栏中的铲子道具（prop type = 0）
        ↓ 拖到目标草地格
oI.Yb：移除来源铲子，发出 sS.At(side, x, y)
        ↓
BattleScene.p$：2_0/2_1 → 1_0/1_1，并替换贴图
        ↓
普通士兵放置校验通过（阵营、地块、占用、金币）
```

因此，能够在铲出的地块放兵的关键不是“给单位增加例外规则”，而是把目标格的地图码从 `2_x` 改成同阵营的 `1_x`。普通士兵后续仍走正常的放置流程。

## 2. 地图数据与关卡生成

### 2.1 固定地图块

原始 `s4`（重建为 `src/battle/MapData.js`）的构造函数内直接保存 4 个地图块，枚举名对应：

| `mapIndex` | 关卡名 | 原始标识 |
|---:|---|---|
| 0 | JuLu | `te` |
| 1 | YunMengZe | `le` |
| 2 | HuLaoGuan | `ce` |
| 3 | ChiBi | `ue` |

每张地图都是 8 列 × 10 行。每个元素是 `kind_lane` 格式：

| 地图码 | 含义 | 渲染 | 士兵放置 |
|---|---|---|---|
| `0_0` / `0_1` | 行军路线 | `road_<mapIndex>.png` | 不可放普通士兵；A* 可通行 |
| `1_0` / `1_1` | 已开垦空间 | `space_<mapIndex>.png` | 仅对应阵营可放普通士兵 |
| `2_0` / `2_1` | 草地/未开垦地块 | `grass_<mapIndex>_<lane>.png` | 普通士兵不可放；是铲子的目标 |

`lane` 是阵营侧，但不要只根据布尔值名称猜测“玩家/对手”的映射。当前重建 `MapData.isBuildableForSide` 使用 `side=true → lane 1`、`side=false → lane 0`；而原始 `p$` 明确使用 `true → 1_0`、`false → 1_1`。原始免费铲子路径由 `G$` 以 `true` 创建玩家铲子，因此两套代码的布尔侧别需要在 Unity 适配层集中校准，不能散落在各个校验函数中。

### 2.2 `changeMap` 与路径

`MapData.changeMap(mapIndex)` 做四件事：

1. 通过 `mapDataBlockByIndex` 取固定地图块。
2. 把固定数组复制到可变运行时数组 `pe`，避免直接改模板。
3. 设置双方入口、起点、终点和路线标记。
4. 调用 A* 计算 `Le`（玩家）和 `me`（对手）路径。

A* 只把 `0_0`、`0_1` 设为可通行，且只搜索上下左右四邻居。铲子只改变 `2_x → 1_x`，不会改变路线，因此不需要重新计算 A* 路径。

### 2.3 地图视觉生成

战斗场景打开时，原始 `onOpened` 调用 `$q → Vq → Qq → Zq → Kq`：

- `$q/Yq`：创建或复用每个格子的 `Image`，名称为 `${x}_${y}`，尺寸 80×80，位置为 `x*80, y*80`。
- `Vq`：按地图码选择道路、空间或草地贴图，并将瓦片放入 `road` / `highGround` 层。
- `Qq`：在路线和可部署地块相邻处画边界线，同时画地图外框。
- `Zq/Kq`：设置分界线、终点和路线提示。

- `src/battle/MapData.js:122-297`
- `src/rendering/MapRenderer.js:31-115`
- `src/presentation/LayaMapRenderer.js:49-109, 189-213`
- `src/scenes/BattleSceneController.js:179-204`

原始证据：`bundle:12194-12847`（地图块、A*、`changeMap`）、`bundle:57303-57329`（瓦片池）、`bundle:58750-58790`（按地图码铺图）。

## 3. 铲子的来源与对象模型

### 3.1 铲子是牌池字和道具对象两种形态

原始配置中：

- 道具定义 `name: "shovel"`、显示文字“铲子”、说明“可以开荒的铲子”：`bundle:3365-3367`。
- 三组初始牌池 `eh/ah/nh` 都是 108 个元素，其中“铲”出现 11 次：`bundle:11969`。
- `vN.xO` 在 `roundDay <= 3` 时统计玩家牌池里的“铲”，每 5 个额外向玩家和对手牌池各加入 1 个：`bundle:46529-46545`。

重建代码已经实现了牌池侧的注入：`src/deck/DeckManager.js:58-65, 175-206`。但“铲”进入刷新栏后需要转换为道具对象，不能当作普通士兵单位。

### 3.2 刷新栏中的铲子道具

原始刷新逻辑 `refresh(a,b)` 明确分支：

```text
普通字牌：vc.gP(3, a, true, b)       → 创建刷新栏单位
铲子牌：  vb._A(true, 0, 3, b)        → 创建 prop type=0
```

`type=0` 在道具工厂中注册为 `oI`，即铲子类：`bundle:26860-26862`。`oI.init` 会创建 `shovelShadow.png`，并根据是否为金铲选择 `shovel_1.png` 或 `shovel_2.png`：`bundle:25998-26044`。

### 3.3 观看广告获得铲子

战斗场景另有一个铲子广告入口，不等同于牌池抽牌：

- `w$` 打开/关闭铲子广告模式，使用地图状态 `map.ve`；`map.we` 表示铲子发放流程已经执行，避免重复触发：`bundle:58606-58639`。
- `zq` 点击广告后，收集刷新栏空槽，最多取 2 个槽位：`bundle:59007-59035`。
- `G$` 将铲子从广告位置动画到刷新栏目标槽，动画完成后调用 `vb._A(true, 0, 3, slot)` 创建铲子道具：`bundle:58695-58723`。
- 第一次使用走免费分支并设置 `player.hasUsedFreeShovel=true`；之后走广告服务，最多仍发 2 把：`bundle:59035-59055`。

玩家数据中的 `hasUsedFreeShovel` 有持久化字段和 getter/setter：`bundle:8347-8348, 8576-8577, 8860-8867, 8977-8984`。

## 4. 铲地块的完整调用链

### 4.1 交互层：点击/拖拽铲子

原始输入管理器的行为是：

1. `onMouseDown` 通过命中测试找到刷新栏或地图对象。
2. 找到 `rD` 道具对象时，将它记录为当前拖拽物；铲子 `oI` 的 `onMouseDown` 会隐藏阴影。
3. 鼠标移动超过阈值后进入拖拽状态。
4. 鼠标释放时，`UH` 组装 `{type:1, source, target, nm}` 操作并交给 `r0._Y`。
5. `r0._Y` 将 `type=1` 分派到 `SY`，道具源再进入 `RY`。
6. `RY` 调用道具校验；通过后执行 `oI.Yb(target, containerManager)`。

对应证据：`bundle:49000-49110`（操作分派）、`bundle:49100-49480`（单位/道具移动校验）、`bundle:59476-59577`（输入、释放、`refresh`）。

### 4.2 规则层：`oI.Yb` 消费铲子并发事件

`oI.Yb` 的核心顺序是：

1. 查询目标容器中的对象。
2. 目标有对象时，按 `nm` 阵营分支处理；必要时移除目标单位，或提示“请先妥善安置农民”。
3. 从来源容器移除当前铲子。
4. 发出 `sS.At(this.nm, target.x, target.y)`，通知战斗场景开垦目标格。
5. 发出 `sS.Lt(this.id)`，让道具管理器移除/回收铲子对象。

精确实现位于 `bundle:25998-26087`。这说明铲子是一次性消耗品，地块改动由场景事件完成，而不是由道具对象直接修改地图数组。

### 4.3 场景层：`p$` 把草地改成可部署地块

战斗场景的事件注册将 `sS.At` 绑定到 `p$`：`bundle:59105`。`p$` 的核心代码只有三步：

```text
pe[x][y] = side ? "1_0" : "1_1"
Lq[`${x}_${y}`].skin = `resources/img/map/space_${mapIndex}.png`
播放 grass → space 的铲地视觉效果
```

证据为 `bundle:58822-58831`。原始的铲子移动辅助函数 `W$` 会在坐标缺省时，从右下向左上寻找本阵营的 `2_0` 或 `2_1`，计算目标格中心，播放铲子飞入动画，动画回调再调用 `p$`：`bundle:58565-58598`。这条辅助路径和玩家直接拖拽道具最终汇合到同一个 `p$` 状态变更。

视觉层使用的资源包括：

- `resources/img/map/grass_<mapIndex>_<lane>.png`
- `resources/img/map/space_<mapIndex>.png`
- `resources/img/props/shovel_1.png` / `shovel_2.png`
- `resources/img/props/shovelShadow.png`
- `prefab/shovelGrass.lh`

重建工程目前只做了资源目录登记：`src/resources/ImageCatalog.js:25-27, 743-745`、`src/resources/PrefabCatalog.js:2492-2494`；真正的铲地行为仍未接入 `src`。

## 5. 铲出后为什么可以放兵

原始拖拽校验 `UY` 对地图单位有明确区别：

- 普通士兵必须落在与自身 `nm` 相同的开放 lane：`nm=true` 时要求 `1_0`，`nm=false` 时要求 `1_1`。
- 农民可以在同阵营的 `1_x` 或 `2_x` 上，但不能放在路线或对手区域。
- 目标已有单位时才进入合成/移动分支；目标是道具时不允许交换。

所以，草地 `2_x` 先被铲成与自身 lane 对应的 `1_x` 后，普通士兵自然通过地图码校验。随后仍会检查目标是否被占用、是否可以支付招募费用，并创建单位。

重建 `src` 中的等价普通放兵顺序是：

```text
BattleInputController.validatePlacement
  1. MapData.isBuildableForSide(side, x, y)
  2. MapTileManager.canPlace(side, x, y)
  3. UnitRegistry.hasBattleOccupant(side, x, y)
      ↓
Economy.payRecruit
      ↓
UnitRegistry.createUnit(BATTLE, text, side, x, y, level)
      ↓失败回滚金币；成功后 DeckManager.consume
```

对应代码：

- `src/battle/MapData.js:236-241`：当前重建只将 `kind=1` 视为普通士兵可部署。
- `src/input/BattleInputController.js:8-12`：地图、禁用地块、占用、金币、创建和消费顺序。
- `src/units/UnitRegistry.js:68-107, 142-163`：单位分类、创建、占位和移动。

这里的 `MapTileManager` 是技能造成的“禁用/阻挡地块”状态，不是铲子开荒状态。它的 `blockTile` 不应被用来实现铲地；铲地需要改变 `MapData.map[x][y]` 的地图码和对应渲染瓦片。

## 7. Unity 落地建议

1. **把地图码作为权威规则状态。** 建议提供 `OpenTile(side, x, y)`，只允许同阵营的 `2_0/2_1` 转换为 `1_0/1_1`，并在越界、游戏结束、占用冲突时失败。
2. **单独建铲子道具容器。** 牌面文字“铲”和刷新栏中的 `ShovelItem` 是两个层次；从刷新栏拖出后要消费道具，不能调用 `UnitRegistry.createUnit`。
3. **事件在动画完成后提交。** 保留原工程的时序：铲子飞行动画完成 → `OpenTile` → 替换 `space` 贴图 → 回收铲子。规则层应防止动画重复回调导致重复开垦。
4. **复用普通放兵校验。** 开垦只负责把 `2_x` 变成 `1_x`，放兵仍按阵营、禁用状态、占用和金币顺序执行。
5. **不要重算路线。** 铲地不改变 `0_x` 路线；只刷新目标瓦片和部署合法性即可。
6. **区分两类“地块不可用”。** `MapTileManager` 的技能禁用是附加状态；`2_x` 是地图本身的未开垦码，两者应在校验与存档中分开表示。
7. **集中维护布尔侧别与 lane 的映射。** 原始 `p$` 的 `true→1_0` 与当前重建 `MapData` 的 `true→lane 1` 不一致；建议使用 `SideToLane(side)` 单点转换，并让铲地和普通放兵共用它。
