# 当前工程武器合成接入方案（已执行）

> 执行日期：2026-08-30
> 范围：武器目录、碎片合成、装备、回收、奖励、存档与战斗装载接入

## 1. 最终架构

武器业务已经收敛到 `GameBattle/Weapon`，由 `BattleModule` 持有一个普通 C# 对象 `WeaponManager`。它不参与 TEngine 模块注册，也不单独拥有生命周期。

```text
GameModule.Battle
├─ BattleModule 生命周期
├─ BattleRuntime
└─ WeaponManager
   ├─ WeaponCatalog
   ├─ WeaponCollectionState
   ├─ WeaponBattleRewardPolicy
   └─ PlayerPrefs JSON 存档
```

业务访问入口统一为：

```csharp
GameModule.Battle.Weapon
```

当前四个基础武器 ID 保持与 Luban 配置一致：

| 槽位 | 类型 | 默认 ID |
|---|---|---:|
| Bow | 弓 | 1 |
| Spear | 枪 | 11 |
| Knife | 刀 | 21 |
| Sword | 剑 | 32 |

## 3. BattleModule 接入

`IBattleModule` 新增：

```csharp
WeaponManager Weapon { get; }
```

`BattleModule.OnInit()` 从 `ConfigSystem.Instance.Tables` 创建 `WeaponManager`；`Shutdown()` 先调用 `SaveIfDirty()`，再释放引用。`HotFixModules` 的生产顺序保持为：

```text
GameFUI → BattleModule → FreezeBindings
```

组合根只注册现有业务模块，武器管理器不再进入 `ModuleSystem`。

## 4. 战斗装载与运行时隔离

开战入口在 `GameApp` 中先读取并冻结：

```csharp
BattleWeaponLoadoutDto weapons =
    GameModule.Battle.Weapon.CreateBattleLoadout();
```

之后把它放入 `BattleLoadoutDto.Weapons`。`BattleRuntimeFactory` 只从该不可变装载创建 `BasicWeaponResolver`，再交给 `UnitRegistry` 和 `SoldierBase`。战斗运行中不读取可变的 `WeaponManager`，局外改装只影响下一局。

启动上下文匹配同时比较四个武器槽，避免重试时复用不匹配的地图或装备上下文。

## 5. 战斗奖励

在 `BattleModule.Update()` 检测到结果冻结后，流程为：

```text
Running → Settling
       → Runtime.EnterSettling()
       → WeaponManager.ApplyBattleResult(loadout, result)
       → 打开结算窗口
```

状态已经切换为 `Settling` 后，后续帧不会再次进入该分支，因此同一局只提交一次。奖励使用本局 `MapId`、随机种子和胜负结果，并在结算窗口打开前先完成存档。

存档失败时记录错误，战斗结算仍然完成，但未保存的奖励不会替换内存状态，也不会传给结算窗口。

## 6. 存档格式

存档只使用一个 PlayerPrefs JSON 键：

```text
PLAYER_WEAPON_PROGRESS_V1
```

数据结构使用数组以兼容 Unity `JsonUtility`：

```text
WeaponProgressSaveData
├─ schemaVersion
├─ revision
├─ fragmentRecords[]  { weaponId, totalFragments }
├─ equipRecords[]     { slot, weaponId }
└─ pendingRecords[]   { weaponId, pendingCount }
```

所有合成、装备和回收操作都遵循：

```text
复制当前状态 → 在副本上变更 → 保存副本 → 保存成功后替换当前状态
```

已装备武器至少保留一件完整数量；完整数量和余数均由累计碎片与配置中的 `fragmentNum` 派生。
